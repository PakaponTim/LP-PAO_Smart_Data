# บันทึกการปรับปรุง 7 กันยายน 2569

## สิ่งที่ทำ

1. เพิ่ม Login จริง, scrypt, HttpOnly session, CSRF, สิทธิ์ admin/operator/viewer, กุญแจ Extension และการเพิกถอน ปิดการเปิดไฟล์สำรองผ่าน static server และเปิดตรวจใบรับรอง SMTP
2. เปลี่ยนการรับข้อมูลให้ตรวจโครงสร้าง บันทึกเป็น transaction พร้อม ledger ป้องกัน request เดิมซ้ำ และตอบสถานะ DB/Excel แยกกัน แก้คิวที่ไม่ฟื้นหลัง error
3. แก้การรวมปริมาณน้ำในอ่างรายวัน และชื่อฝนสะสม 3 วัน รักษาคอลัมน์และข้อมูลประวัติเดิมไว้
4. Cache สถิติ 60 วินาที และ Dashboard/GIS/risk 30 วินาที ล้าง cache หลังรับข้อมูลใหม่ ลด polling สถานะเป็น 15 วินาทีเฉพาะแท็บที่มองเห็น
5. แยก collector/storage/auth/routes และแยก JS/CSS ออกจาก HTML โดยรักษาลำดับการโหลดเดิม เปลี่ยน dev/build ให้ใช้หน้า UI จริง
6. เพิ่มหน้าติดตามเหตุ ผู้รับผิดชอบ ประวัติผู้ดำเนินการ ข้อมูลขาดรายสถานี และงานบันทึก/สำรองที่ต้องลองใหม่

## ผลตรวจ

- MySQL ที่ตรวจพบ: 5.7.24 จึงไม่ใช้ window functions หรือ CTE
- ทดสอบ 10 รายการผ่าน รวม integration กับ schema ชั่วคราว: ingestion 5 ประเภท, duplicate request, rollback หลังบันทึกบาง chunk, ประวัติเรื่องร้องเรียน, สูตรรวมเขื่อน
- ทดสอบ Excel จริงในไฟล์ชั่วคราว: outbox อยู่หลังสร้าง instance ใหม่, รวม 2 batches เป็น 1 write, replay ไม่เพิ่มแถวซ้ำ, error ยังรักษาข้อมูลไว้
- ตรวจ syntax ของ JS และ inline scripts; build UI ผ่าน
- ทดลอง Login และ Dashboard ผ่าน Browser พบหน้าจอโหลดข้อมูลได้ ไม่มี error ที่เครื่องมือตรวจพบในขั้นนั้น
- Smoke HTTP ของแอปจริงบนพอร์ตทดสอบ: status, dashboard-summary, risk-index, GIS, incidents, data-quality, operations/status และ data-gap-check ตอบ 200; ไฟล์ backup และ `.env` ตอบ 404

## ขอบเขตที่ยังต้องระวังในการใช้งาน

- ยังไม่ได้ทดสอบจับคู่ Extension จริงด้วยบัญชีผู้ดูแลของผู้ใช้ และไม่ได้สั่งส่งอีเมลทดสอบ
- ใช้หน้าเว็บต้นทางที่เปลี่ยนได้ จึงต้องตรวจผล collector หลัง reload Extension
- ข้อมูลเก่ามีชื่อ field และนิยามที่คลาดเคลื่อน ไม่ได้แก้หรือคาดเดาค่าย้อนหลัง
- หน้าพยากรณ์เดิมเป็นสูตร/ภาพจำลอง ไม่ใช่โมเดล AI ที่ผ่านการประเมินความแม่นยำ การแก้รอบนี้ไม่ใช่การรับรองพยากรณ์
- พิกัดที่ไม่มีค่ากำหนดใช้ศูนย์กลางอำเภอ พร้อม `coordinatePrecision` ไม่ใช่ตำแหน่งเครื่องวัดจริง
- จุดข้อมูลที่ไม่เคยเข้าระบบไม่อยู่ในทะเบียนสถานีที่อนุมานจากฐานข้อมูล ต้องมี station master จากผู้ดูแลจึงจะตรวจความครบถ้วนทั้งหมดได้
- ระบบยังเป็น single-process; หากต้องเปิดหลาย instance ต้องย้าย session/file stores/outbox ไปที่ shared store และใช้ distributed locks
- ไม่มีการลบข้อมูลเดิม สำเนา source ก่อนแก้อยู่ใน `.work-backups/` ตารางเพิ่มเติมเป็น additive migration
