1. ภาพรวมสถาปัตยกรรมการทำงาน (System Architecture)

ผังการทำงานเชื่อมโยงระหว่าง API ต้นทาง, Server (Smart Sleep + curl_multi), ฐานข้อมูล water_system2 และระบบแจ้งเตือน

📋 System Log Center v2

บันทึกผลสำเร็จ/ล้มเหลวของทุกด้าน + เวลารันจริงลง tbl_system_logs, แสดง Heatmap 48 ช่องรายวัน, คิว Retry อัตโนมัติแบบไม่บล็อกงานหลัก และ Export CSV Audit Log

🛡️ Subdomain 24/7 Safeguards

มี .htaccess ป้องกันไฟล์ลับ 4 จุด (Root, runtime/, php_server/, cloud_snapshots/), Atomic File Lock, Log Rotation 5 MB + Housekeeping 30 วัน และ /api/health สำหรับ Uptime Monitor

💾 Disaster Recovery (4 ชั้น)

มี Local DB Spool พักข้อมูลเมื่อ DB ดับ + Auto Backup (.sql.gz) ทุกวัน + GitHub Cloud Failover Alert + โหมดดูฉุกเฉิน (emergency_cloud.html)

3. ภาพประกอบส่วนประกอบหลักของระบบ (Visual Walkthrough)

ภาพหน้าจอจริงของหน้า Dashboard, แผนที่วิเคราะห์ความเสี่ยง, ตัวดึงข้อมูล และระบบตั้งเวลา

1) หน้า Dashboard ภาพรวมหลัก

สรุปดัชนีความเสี่ยงทั้ง 13 อำเภอ จ.ลำปาง, แผนที่ GIS, สถานะระดับน้ำ, อ่างเก็บน้ำ, PM 2.5 และเรื่องร้องเรียน

2) วิเคราะห์ระดับน้ำและปริมาณฝน

เปรียบเทียบระดับน้ำปัจจุบันกับระดับตลิ่งซ้าย แนวโน้มขึ้น-ลง และกราฟย้อนหลังรายสถานี

3) สถานการณ์อ่างเก็บน้ำ / ภัยแล้ง

ติดตามปริมาณน้ำกักเก็บของอ่างขนาดใหญ่ (กิ่วลม, กิ่วคอหมา, แม่มอก) ขนาดกลาง และขนาดเล็กครบ 36 แห่ง

ดึงค่าฝุ่น PM 2.5 และค่าเฉลี่ย 24 ชม. ของสถานีในจังหวัดลำปางครบทุกอำเภอ

ดึงตรงจาก Traffy Public API ไม่ต้องล็อกอิน พร้อมแยกงาน อบจ.ลำปาง และบันทึกประวัติการเปลี่ยนสถานะ

STEP 1 — STEP-BY-STEP PUSH TO GITHUB

ขั้นตอน Push โค้ดขึ้น GitHub อย่างละเอียดและปลอดภัย 100%

🔑 เปิดหน้าสร้าง GitHub Token →
① เช็กไฟล์ลับ & .gitignore

ตรวจด้วย git status ให้แน่ใจว่าไม่มีไฟล์ความลับ (.env, runtime/, deploy_server/, *.zip) ติดเข้าไป

git status --short
② ซิงก์ Snapshot จาก GitHub ก่อน

GitHub Actions คอมมิต cloud_snapshots/ ทุก 30 นาที จึงต้องดึงมาต่อท้ายก่อนเสมอ เพื่อไม่ให้ Push ชนกัน (Non-fast-forward)

git pull --rebase --autostash origin main
③ Commit เฉพาะโค้ดที่ทดสอบแล้ว

สเตจโค้ดและคู่มือแล้วสร้าง Commit (หรือรันทดสอบ verify_system_v2.php ก่อนคอมมิต)

git commit -m "docs & v2 update"
④ Push ขึ้น GitHub + เช็ก Actions

ใช้สคริปต์ push_to_github.bat หรือรันคำสั่งด้านล่าง แล้วเปิดแท็บ Actions ดูติ๊กเขียว

git push -u origin main
แบบที่ 1 (แนะนำ): ใช้ PowerShell + Token (1 ครั้งจบ)
  1. เปิด github.com/settings/tokens/new
  2. ติ๊กถูกช่อง repo และ workflow → กด Generate token แล้วก๊อปปี้รหัส ghp_...
  3. เปิด PowerShell พิมพ์ cd D:\Water_System2 แล้วรัน:
    C:\laragon\bin\git\bin\git.exe push -u origin main
  4. ใส่ Username = PakaponTim และ Password = วาง Token ghp_...
แบบที่ 2 (ไม่ต้องใช้คำสั่ง): ลากไฟล์วางบนหน้าเว็บ GitHub
  1. เปิด Repo PakaponTim/Water_System2 คลิก uploading an existing file
  2. เปิดโฟลเดอร์ D:\Water_System2\deploy_server\Water_System2 กด Ctrl+A ลากวางทั้งหมดแล้วกด Commit changes
  3. กด Add file → Create new file พิมพ์ชื่อไฟล์:
    .github/workflows/collect_every_30min.yml
  4. วางเนื้อหา Workflow แล้วกด Commit changes → เปิดแท็บ Actions
เมื่อเปิดหน้า GitHub Actions (/actions) อยู่ — ต้องคลิกอะไรต่อ?
  1. ตรวจให้แน่ใจว่า Push โค้ดล่าสุดขึ้น GitHub แล้ว: จากเครื่องคอมฯ กดรัน push_to_github.bat (หรือ git push -u origin main) เพื่อให้ Commit ใหม่ล่าสุดไปอยู่บน GitHub ก่อน
  2. สั่งทดสอบรันบนหน้า Actions: คลิกชื่อ Water_System2 Cloud Collector (Every 30 Minutes) ที่เมนูซ้าย → กดปุ่ม Run workflow ด้านขวาบน → เลือก Branch: main แล้วกดปุ่มเขียว Run workflow
  3. รอประมาณ 1 นาที: รีเฟรชหน้าแล้วตรวจให้ขึ้นเครื่องหมาย ✅ สีเขียว และมีการเก็บไฟล์ลง cloud_snapshots/
  4. ตั้งค่า Domain หลัก + สำรอง: แก้ไขไฟล์ domain_config.json (ตั้ง primary_domain และ backup_domain ได้ถึง 2 โดเมน) หรือกรอกผ่านหน้า server_setup.php เพื่อให้ GitHub Actions ปลุกทั้ง 2 โดเมนและแจ้ง Failover อัตโนมัติ (หรือตั้ง Secret WATER_SERVER_CRON_URL / WATER_SERVER_BACKUP_CRON_URL)
STEP 2

ก๊อปปี้โฟลเดอร์ไปวางบน Server (คัดเฉพาะไฟล์ใช้งาน)

  1. รัน php php_server/build_server_package.php เพื่อสร้างแพ็กเกจปลอดความลับ (0 Secrets) ที่ deploy_server/Water_System2_Server_Deploy.zip (~4.5 MB)
  2. นำโฟลเดอร์ Water_System2 ไปวางบน Subdomain / Folder ของ Server (พร้อมไฟล์ป้องกัน .htaccess ทั้ง 4 ชั้น)
  3. ไม่ต้องอัปโหลด โฟลเดอร์ node_modules/, runtime/, scratch/ หรือ .env จากเครื่องพัฒนา
STEP 3

ตั้งค่า MySQL บน Server และสร้างตารางอัตโนมัติ

  1. เปิดเบราว์เซอร์ไปที่หน้าตั้งค่าบน Server:
    http://ชื่อเซิร์ฟเวอร์/Water_System2/server_setup.php
  2. กรอก Host, Database Name, Username, Password ของ MySQL บน Server (เมื่อตั้งค่าแล้ว การแก้ไขจากภายนอกต้องยืนยันรหัสผ่านเดิม)
  3. กดปุ่มเขียว "💾 บันทึกค่าและตรวจสอบตารางฐานข้อมูลอัตโนมัติ" (ระบบสร้างครบทั้ง 10 ตาราง รวม tbl_system_logs ให้อัตโนมัติ)
  4. กดปุ่มน้ำเงิน "🚀 ทดสอบดึงข้อมูล... (cron.php)" เพื่อดูดข้อมูลชุดแรกเข้า Server
STEP 4

เปิด Smart Sleep + ตั้งแจ้งเตือน Gmail/LINE แล้วปิดคอมได้เลย

  1. ตั้งปลุก Server 24 ชม.: เพิ่ม Secret WATER_SERVER_CRON_URL ใน GitHub ชี้มาที่ Subdomain .../cron.php และตั้ง Uptime Monitor ชี้ที่ endpoint.php?r=/api/health (หรือเปิด worker.php?action=start)
  2. เปิดหน้า notification.html ใส่ LINE Token + Group ID และเพิ่มอีเมลผู้บริหารที่ต้องการรับแจ้งเตือน แล้วกดทดสอบส่งอีเมล
  3. Traffy Automation: ระบบดึง Traffy Public API อัตโนมัติโดยไม่ต้องใช้ Chrome Extension (หรือใส่ org_id/uuid / LINE Token ใน UI และต่อยอด Traffy Exchange API get-auth ได้)
  4. เสร็จสมบูรณ์! ปิดคอมพิวเตอร์ได้เลย Server + GitHub Actions จะทำงานเก็บข้อมูลและแจ้งเตือนต่อตลอด 24 ชม.
